# Crick English spectator Android app

Native Kotlin and Jetpack Compose client for the Department of English cricket tournament.

## Backend and calculations

The app reads public records anonymously from `https://pbdb2.duckdns.org`. It discovers the active season and loads teams, players, published fixtures, finalized legacy player figures and published season archives. Detail screens load the optional scoring log on demand.

The published match scorecard supplies scores and player figures. Embedded `scorecard.playerStats` takes precedence over legacy records, including an authoritative empty array. Rankings, season totals and profiles count published completed matches. Highest strike rate requires at least 10 balls faced across those matches. League points and NRR follow the website, including all-out quota and actual balls for innings closed early. All times display in Asia/Dhaka.

Home and match details poll summaries every 10 seconds while the app is visible. Refresh keeps the previous successful scores during connection failures and preserves tabs and navigation state. Ball-log refresh failures are visible separately. Explicit innings selection is preserved, while the default follows the latest innings. Public data is kept in memory for the current session.

## Build on Windows

Install JDK 17 and Android SDK Platform 35. Set `JAVA_HOME` and `ANDROID_HOME`, or set the SDK path in an ignored `local.properties`. Use the included Gradle 8.9 wrapper.

```powershell
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug
```

The debug APK is written to `app/build/outputs/apk/debug/app-debug.apk`. The application ID is `org.crickenglish.app`. It supports Android 7 and newer, with Java time API desugaring for older phones.

The build accepts an AI Studio `debug.keystore` in the project root when provided. Otherwise it uses the local Android debug signing key. Updating a previously installed AI Studio APK requires the original signing key. Release signing uses `KEYSTORE_PATH`, `STORE_PASSWORD` and `KEY_PASSWORD` with the `upload` key alias.

## Verification

The suite includes 13 tests covering calculations, live anonymous PocketBase reads, navigation and refresh, season changes, saved match tabs, and replay parity. The eight replay scenarios in `app/src/test/resources/website-replay-parity.json` contain inputs and expected delivery states generated by the website's `src/scoring.ts`. They cover extras, run-outs, retired batters, explicit strike swaps, over changes, innings closed early, signed adjustments, and a chase resumed after a score deduction.

The live API test requires a connection to the existing tournament backend. It performs read-only requests. Robolectric uses Android 35 and downloads its Android runtime from Maven Central on the first test run.

# Crick English spectator Android app

Native Kotlin and Jetpack Compose client for the Department of English cricket tournament.

## Backend and calculations

The app reads public records anonymously from `https://pbdb2.duckdns.org`. It discovers the active season and loads teams, players, published fixtures, finalized legacy player figures and published season archives. Detail screens load the optional scoring log on demand.

The published match scorecard supplies scores and player figures. Embedded `scorecard.playerStats` takes precedence over legacy records, including an authoritative empty array. Rankings, season totals and profiles count published completed matches. Highest strike rate requires at least 10 balls faced across those matches. League points and NRR follow the website, including all-out quota and actual balls for innings closed early. All times display in Asia/Dhaka.

Home and match details poll summaries every 10 seconds while the app is visible. Refresh keeps the previous successful scores during connection failures and preserves tabs and navigation state. Ball-log refresh failures are visible separately. Explicit innings selection is preserved, while the default follows the latest innings. Public data is kept in memory for the current session.

## Build on Windows

Install JDK 17 and Android SDK Platform 35. Set `JAVA_HOME` and `ANDROID_HOME`, or set the SDK path in an ignored `local.properties`. Use the included Gradle 8.9 wrapper.

```powershell
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug
```

The debug APK is written to `app/build/outputs/apk/debug/app-debug.apk`. The application ID is `org.crickenglish.app`. It supports Android 7 and newer, with Java time API desugaring for older phones.

The build accepts an AI Studio `debug.keystore` in the project root when provided. Otherwise it uses the local Android debug signing key. Updating a previously installed AI Studio APK requires the original signing key. Release signing uses `KEYSTORE_PATH`, `STORE_PASSWORD` and `KEY_PASSWORD` with KEY_ALIAS selecting the key alias, defaulting to upload.

## Verification

The suite includes 13 tests covering calculations, live anonymous PocketBase reads, navigation and refresh, season changes, saved match tabs, and replay parity. The eight replay scenarios in `app/src/test/resources/website-replay-parity.json` contain inputs and expected delivery states generated by the website's `src/scoring.ts`. They cover extras, run-outs, retired batters, explicit strike swaps, over changes, innings closed early, signed adjustments, and a chase resumed after a score deduction.

The optional live API test requires a connection to the existing tournament backend. It performs read-only requests. Robolectric uses Android 35 and downloads its Android runtime from Maven Central on the first test run.

## Automatic signed releases

Pushing to main runs the Signed Android release workflow. The same workflow can be started from the Actions page using Run workflow on main. A successful run tests the app, runs release lint, builds and verifies a signed release APK, and publishes a new GitHub Release. Each release includes Crick-English.apk, its SHA-256 checksum, package information and the signing certificate.

Download the current APK from https://github.com/madhu734/CE-app/releases/latest/download/Crick-English.apk. Older releases remain available on the Releases page.

The workflow restores a fixed key from repository Actions secrets KEYSTORE_BASE64, STORE_PASSWORD, KEY_PASSWORD and KEY_ALIAS. ANDROID_SIGNING_CERT_SHA256 is a repository variable containing the public certificate fingerprint. Signature verification must match that fingerprint before publication. Restore the established key and credentials when recovering signing configuration. The key is generated once during initial setup and retained for future releases.

CI supplies APP_VERSION_CODE as UTC seconds since 2020, keeping successive builds installable as updates. APP_BUILD_NUMBER appends the workflow run number to the base app version name. The version code supports Android's integer range through 2088. Each release has a distinct android-<versionCode> tag and is tied to its exact source commit. A build whose commit has been superseded on main can publish its archive without becoming the latest release.

A private signing backup is kept on the setup PC under %LOCALAPPDATA%\CrickEnglish\Signing. Keep that backup with the app's maintenance records. The first fixed-key release replaces the earlier locally debug-signed test installation. All subsequent release APKs use the fixed release certificate.

The default test suite uses local fixtures so publishing remains independent of the live tournament server. To run the anonymous live API check as well, use:

```powershell
.\gradlew.bat :app:testDebugUnitTest -PliveApi=true
```
